## Important judgments and proofs

### Source-selected preparation is not native graph expansion

The initial regression failed on valid `page = 'p-auto'`. Whitespace, quoted,
escaped JSON-expression and multiline property spellings now use the shared
production-parser selection and bounded opening-tag token extent. Prose/code
lookalikes are untouched. Original-source binding, collision/reserved-row policy,
interleaved object/span order and exact prepared model/state proof remain intact.
Key preparation additionally proves raw comments stay with the same page/block
ordinal while provisional identities become durable.

The executed CLI fixture exposed an important operation distinction: a reachable
PageLink back to the main page creates a cycle, outside the current native writer
profile. That valid source can prepare, but executed push refuses **before source
or native effects**. An acyclic named-page spelling variant completes preview →
first save → pull/repeat with retained associations and byte/mtime no-op. The
coverage matrix records this distinction instead of weakening native preflight.

### Flow YAML keeps author bytes, not generic serde spans

Collection spans were verified to be incomplete; no generic scalar-span assumption
was added. Existing granit start/end events pair flow collections, including nested
quoted/commented arrays and maps. Selected comments remain (possibly as standalone
comments before a normalized replacement). Unrelated author values/style/comments,
raw body, BOM and CRLF survive. Envelope insertion supports commented/multiline
YAML flow maps, not only literal one-line JSON. Aliases/anchors/tags/merge/duplicates
remain restricted by the actual parser options.

The real CLI/HTTP fixture starts with a BOM/CRLF whole-flow header, edits title/tags/
description offline, previews without effects, first-binds in a publication,
records native contributor/watermark defaults, saves, adopts remote title metadata,
then proves unchanged push/pull bytes/mtime and native node continuity. Unknown
author flow entries retain exact source throughout.

### Comments have explicit source ownership

Standalone one-block-comment MDX expressions attach to the following same-page
block, before/after its Key. They are source-only trivia, absent from the document
model/editor fingerprints/native effects. Inline/trailing/orphan comments and
ambiguous comments before Page definitions refuse; native discussion is not enabled.

Preparation/tidy/local edits/no-op saves preserve them. On changed remote bodies,
raw comment text follows retained same-page block identity; reorder is supported.
Deleted or cross-page anchors refuse local adoption, even under `--take remote`.
The author must explicitly move/remove the comment before trying again. This is
a visible correctness boundary, not an implicit lossy relocation policy.

Pure tests prove multiline/Unicode/BOM/CRLF/comment meaning, provisional-key
preparation, tidy, rename, same-page reorder, deletion/cross-page refusal and stale/
tampered source plans. The real CLI/HTTP workflow proves local comment-only changes
remain empty-effect saves, remote type change retains entity/comment, and remote
anchor deletion leaves source/mtime/receipts unchanged even with `--take remote`.
The existing real Phoenix poke-to-file case now includes a renamed block's comment
and exact repeat no-op. There is no second saved body/history or universal trivia tree.

### Coverage is an account, not a new framework

The maintained matrix covers every upstream block-kind name, current source/native
families, metadata/resources and read/edit/write/structural/refresh/recovery/export
boundaries. It names partial/shared versus dedicated evidence, independent native
expected values versus same-library render controls, actual binary/HTTP/Phoenix
versus actual Yjs versus specific prior deployed checks.

New native tests independently assert code bytes/inactive text and image source/
fallback/dimensions/alt, reject local-resource fields, and exercise every unsupported
pinned richer block-kind plus representative unknown attributes on ordinary content.
Valid typed non-HTTP resources and unsupported comments also fail native preflight
without requests or file writes. No all-rich-content implementation was smuggled
into the coverage ticket; gaps remain visible as gaps.
