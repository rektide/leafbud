# Leaflet lexicon pin — generated code provenance

The generated modules in this crate (`com_atproto*`, `pub_leaflet*`,
`site_standard*`, `builder_types.rs`, all `// @generated by
jacquard-lexicon. DO NOT EDIT.`) are **the pin**: committed generated code
from a SHA-pinned lexicon source, per `experiments/04-jacquard/REPORT.md`
§6 verdict (b) and `design/springleaf.glm53m.md` §Updates. Regeneration is
a deliberate, reviewed step — never automatic.

## Invocation (mirrors `experiments/04-jacquard/probe-codegen.sh`, narrowed)

```sh
JQ=~/archive/nonbinary.computer/jacquard
LEAFLET=~/archive/hyperlink-academy/leaflet   # must be at 600c7b5f
IN=$(mktemp -d) && OUT=$(mktemp -d)

cd "$LEAFLET" && git rev-parse HEAD            # verify the pin first

cd "$LEAFLET/lexicons"
fd -e json . pub/leaflet site/standard | while read -r f; do
  cp "$f" "$IN/$(echo "$f" | tr '/.' '__').json"
done
cp com/atproto/repo/strongRef.json "$IN/com__atproto__repo__strongRef.json"
cp com/atproto/label/defs.json      "$IN/com__atproto__label__defs.json"

"$JQ/target/release/jacquard-codegen" -i "$IN" -o "$OUT"

cp "$OUT"/*.rs "$OUT"/com_atproto* "$OUT"/pub_leaflet* "$OUT"/site_standard* \
   <springleaf>/crates/leaflet/src/
# then re-sync the "Generated lexicon bindings" declaration block in
# src/lib.rs from $OUT/lib.rs (the only hand-merged part)
```

Staged filenames are irrelevant — the codegen keys on the JSON `"id"`.
The `com_atproto` namespace here contains only the two dependency docs
(strongRef, label defs), not the whole atproto suite; `parts.*` (non-NSID
fragments) is not referenced by `site.standard.*`/`pub.leaflet.*` and is
excluded.

## Runtime dependencies (intentionally minimal)

```toml
jacquard-common = { version = "=0.12.1", default-features = false, features = ["std"] }
jacquard-derive = "=0.12.1"
jacquard-lexicon = { version = "=0.12.1", default-features = false }
```

No default features: drops `reqwest-client`, `service-auth`, `crypto*`,
compression. `jacquard-lexicon` without `codegen` drops the syn/quote/
prettyplease toolchain. `jacquard-derive` (proc macro) needs
`jacquard-lexicon/codegen` and re-adds it transitively at compile time
only. Versions are exact-pinned (`=0.12.1`) to match the codegen binary's
workspace version — see the design doc's jacquard dependency-risk note
(single-maintainer upstream, 0.12→0.13 expected to break).

## Adaptations of the crate to the generated code

- The generated tree expects **crate-root placement** (`extern crate
  alloc`, `crate::builder_types` paths), so the namespace modules live at
  `src/` root and `src/lib.rs` carries the declarations; the generated
  `lib.rs` itself is replaced by the hand-written root.
- Crate `features` (`com_atproto`, `pub_leaflet`, `site_standard`, all
  default-on) preserve the generated `#[cfg]` gates verbatim.
- Lint allows (`unused_imports`, `non_snake_case`, `clippy::all`) sit on
  the generated module declarations only.
- Single-variant lexicon unions (e.g. `Document.content`) collapse to the
  bare struct in jacquard's codegen, dropping the `$type` discriminator.
  `record::build_record` re-injects the two wire-required discriminators
  (`pub.leaflet.content`, `pub.leaflet.pages.linearDocument#block`) after
  serialization; deserialization captures them via `extra_data`.

## Regeneration checklist

1. Verify/advance the leaflet checkout SHA; update this file.
2. Run the invocation above; copy the tree; re-sync `lib.rs` declarations.
3. `cargo nextest run -p springleaf-leaflet` — the golden test against
   `experiments/03-post-builder/built-record.json` fails loudly on drift.
4. Review the diff like any hand-written change; commit as its own stage.
